1. نظرة عامة على النظام

نظام النقل في SouqOne هو سوق لخدمات النقل والشحن داخل سلطنة عمان. يربط بين العملاء (الشاحنين) الذين يحتاجون نقل بضائع، وشركات النقل (الناقلين) الذين يملكون مركبات ويقدمون خدمات الشحن. النظام يعمل بنموذج الطلب → العروض → القبول → التنفيذ.

Expo Router v6 (ملفات)
TanStack React Query v5
Zustand + Axios
واجهة عربية RTL بخط Almarai

2. أنواع المستخدمين والأدوار

👤 العميل (الشاحن / Shipper)

من هو: أي مستخدم مسجل في التطبيق

ما يقدر يعمل:
✅ إنشاء طلب نقل جديد (5 خطوات)
✅ تصفح جميع طلبات النقل
✅ مشاهدة العروض المقدمة على طلبه
✅ قبول عرض من ناقل
✅ إلغاء طلبه (إذا كان مفتوح)
✅ متابعة حجوزاته (كمُرسِل)
✅ التواصل مع الناقل (اتصال / واتساب / محادثة)
✅ عرض ملف الناقل

🚚 الناقل (Carrier)

من هو: مستخدم سجّل كناقل عبر شاشة التسجيل

ما يقدر يعمل:
✅ تصفح طلبات النقل المتاحة
✅ تقديم عرض سعر على أي طلب مفتوح
✅ سحب عرضه (إذا بانتظار)
✅ إدارة حجوزاته (كناقل)
✅ بدء رحلة النقل
✅ تأكيد إتمام التسليم
✅ إلغاء حجز
✅ له ملف شخصي عام (تقييم، مركبات، خدمات)

4. سير العمل الكامل (Workflow)

المسار الرئيسي (Happy Path)

1
إنشاء طلب
العميل يملأ نموذج 5 خطوات
2
مفتوح OPEN
الطلب يظهر في القائمة
3
عروض QUOTED
الناقلين يقدمون عروضهم
4
قبول ACCEPTED
العميل يقبل عرض → حجز
5
جارٍ IN_PROGRESS
الناقل يبدأ الرحلة
6
مكتمل COMPLETED
الناقل يؤكد التسليم

5. حالات النظام

حالات طلب النقل (Transport Request)

الحالة المفتاح الوصف الإجراءات المتاحة
مفتوح OPEN الطلب جديد وينتظر عروض من الناقلين تقديم عرض · إلغاء الطلب (صاحب الطلب)
وصلت عروض QUOTED هناك عرض أو أكثر مقدّم على الطلب تقديم عرض جديد · قبول عرض · إلغاء الطلب
مقبول ACCEPTED تم قبول عرض ناقل — يتم إنشاء حجز تلقائياً بدء النقل (الناقل) · إلغاء الحجز
جارٍ التنفيذ IN_PROGRESS الناقل بدأ رحلة النقل تأكيد التسليم (الناقل) · إلغاء
مكتمل COMPLETED تم التسليم بنجاح —
ملغى CANCELLED تم إلغاء الطلب —

الحالةالمفتاحالوصف

10. المشاكل والنواقص المعروفة

⚠️
نظام الإعلانات العام (app/post/) — نموذج النقل غير موجود
في step3.tsx، قسم النقل يعرض "نموذج transport قيد التطوير" بدل نموذج حقيقي. الحل: ربط step1 → transport/new.tsx مباشرة عند اختيار قسم النقل.
⚠️
uploadImages endpoint مضاف لكن غير مستخدم
تم إضافة transportApi.uploadImages لكن لا يوجد شاشة تستخدمه لأن إعلانات النقل بدون صور. يمكن إزالته أو الإبقاء عليه للمستقبل.
⚠️
my-requests تستخدم getAll بدل myRequests
شاشة my-requests.tsx تستخدم transportApi.getAll({ userId }) بدل transportApi.myRequests(). الأفضل استخدام endpoint المخصص /transport/requests/my.
⚠️
التاريخ في new.tsx — حقل نصي عادي
حقل التاريخ scheduledAt يستخدم TextInput بصيغة "YYYY-MM-DD" بدل Date Picker حقيقي. يحتاج تحسين بإضافة @react-native-community/datetimepicker.
💡
لا توجد صفحة تقييم بعد إتمام الرحلة
بعد COMPLETED، لا توجد شاشة لتقييم الناقل أو العميل. ميزة مستقبلية مهمة لبناء الثقة.
💡
لا يوجد نظام إشعارات للنقل
عند تقديم عرض أو قبوله أو بدء النقل، لا يوجد push notification. يحتاج ربط مع نظام الإشعارات الحالي.
💡
لا يوجد تتبع حي للشحنة
أثناء IN_PROGRESS، لا يوجد تتبع GPS حي. ميزة مستقبلية.
✅
API paths تم إصلاحها
جميع مسارات API تتطابق مع الباك اند: /my بدل /mine، /start بدل /in-progress.
✅
خطوة الصور تُتخطى تلقائياً
في نظام الإعلانات العام (post/step2.tsx)، عندما يكون القسم = transport يتم التحويل مباشرة لـ step3.
